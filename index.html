No toy datasets. No following along.

Most courses hand you a clean CSV and a notebook to copy. This one starts where real work starts: a public API, messy documents, and a question somebody actually wants answered. Every session you build the next piece yourself, on your own machine, and it has to run before we move on.

By the last session you are not holding a certificate. You are holding something that works, that you can show someone, and that you can explain line by line — because you wrote it.

How the sessions run

Live, hands-on, and slow enough that nobody is left behind.

You type, not just watch

Laptops open the whole way through. Every command is run by everyone, and we stop when a terminal shows something unexpected — because that is the lesson.

One layer per session

Data, pipeline, storage, models, API, interface, deployment. Each session adds one layer and ends with it working, so progress is visible every week.

Built as a team

We design it together, divide the work, review each other's pull requests, and merge. The same way a real engineering team ships software.

Everything is yours

The repository, the slides, the notes, the data. You leave with the whole project on your own GitHub, not a video you can rewatch.

Modern tools, used honestly

We use AI to write code, then read what it produced and find what it got wrong. Knowing how to check the machine is the skill, not avoiding it.

Nothing is skipped

Virtual environments, environment variables, git, errors at midnight. The unglamorous parts are the ones that stop people, so we do them properly.

From an API call to a running product

The seven layers we build, in order. This is the whole course.

01

Get the data

Call the SEC’s public API and pull 56 real annual reports — the moment the project stops being hypothetical.

02

Build the pipeline

Python that downloads, cleans and splits hundreds of pages into passages a machine can work with.

03

Store it twice

PostgreSQL for the figures, a vector database for the text — and the reason the same project needs both.

04

Add the model

Run a language model on your own laptop, give it the right passages, and get an answer with its sources attached.

05

Put a door on it

Wrap the code in a FastAPI service so something other than your terminal can reach it.

06

Build the screen

The page a person actually types into — and this website, which you are reading now.

07

Ship it

Put it online, keep it running, and learn what changes when other people depend on it.

What MarketLens does

A 10-K runs to a few hundred pages, and the interesting parts are buried in prose. This makes them searchable.

It reads the filings

Apple, Microsoft, Alphabet, Amazon, Meta, Nvidia and Tesla — every annual report from 2018 to 2025, straight from the SEC.

It searches by meaning

Ask about “supply chain worries” and it finds the right paragraph even when those words never appear in it.

It shows its sources

Every answer names the company, the year and the section it came from — so you can check it rather than trust it.
